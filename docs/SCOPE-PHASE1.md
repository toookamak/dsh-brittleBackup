# 阶段一范围：本地导出与导入还原

> **本文是阶段一（本期）的权威范围。** 产品边界的完整集合见 [PROJECT-PLAN.md](PROJECT-PLAN.md) §0；本期对 `U*` 条目的撤销 / 收窄 / 新增以本文 §3 为准。产物格式见 [FORMAT.md](FORMAT.md)，安全策略见 [SECURITY.md](SECURITY.md)。
>
> 定位：**核心就是导出备份、导入还原备份。** 不做任何网络传输，界面与文档仅中文。

---

## 1. 一句话范围

把 DSH 的**配置、插件清单、模型配置、skills** 导出成**一个目录**；再从该目录**导入还原**。导入前必须做兼容性验证，导出必须提供内容勾选。

---

## 2. 本期做什么

### 2.1 导出

- **形态**：一个目录（U30）
- **落点**：用户自选目录（U31）；文件完全由用户管理，插件**不维护导出历史**
- **内容勾选**（导出可选项，逐项可关）：

| 勾选项 | 内容 | 默认 |
|---|---|---|
| profile 配置 | `cordis.patch.yml` 结构化条目、`package.json`、`pnpm-workspace.yaml` 原文 | 开 |
| 插件清单 | name / spec / 实际版本 / 来源 / commit / 用途 / `unportable` 标记 | 开 |
| 模型配置 | provider（key / displayName / api / baseURL / apiKeyEnv）+ models[] + 默认模型 | 开 |
| skills 清单 | 名称 / 描述 / 路径 / scope / 文件数 | 开 |
| skills 文件 | 把 `<DSH_HOME>\skills` 下 user 级 skill **原样复制**到导出目录的 `skills/` | **关**（用户显式勾选） |
| 兜底文档 | 自包含、可单独分享的 Markdown | 开 |

- 密钥永不进入产物（见 [SECURITY.md](SECURITY.md)）。
- 导出前做一次密钥自查扫描；命中即拦截并提示。

### 2.2 导入

流程顺序固定：

```
① 选目录（或选其中的 backup.json）
② 严格校验：format / version / 路径安全 / 条目数
③ 兼容性验证：§7 全 14 项，逐项给出 可自动恢复 / 有风险 / 只能手工
④ 环境差异对照：DSH 版本、缺失插件、缺失 key（U14）
⑤ diff 预览 + 逐项勾选
⑥ 写前快照 → 合并写入（配置按条目 id 合并、插件逐项安装）
⑦ 报告：成功 / 失败 / 需手工 / 需补 key
⑧ 失败回滚到快照；回滚不完整必须显式列出残留
```

- **合并语义**：备份里没有的条目一律不删；`absent[]` 不是删除指令。
- **有 agent 在运行时拒绝写入**（U21）。
- 导入导入装插件期间**关闭设置页不中断**（U25 保留部分）：任务状态在宿主侧，重开设置页可见进度与结果。

### 2.3 本期不做

不做远端：WebDAV、GitHub（Gist 与私有仓库 Contents API）、上传与下载、多目标、每目标凭据、远端历史与保留、远端删除及其安全约束。

不做：一键重启、界面双语与文档多语言、定时 / 自动备份、增量与云同步、多用户共享、产物加密、备份会话历史 / storages / attachments / 登录态 / `node_modules`。

日常只做中文；产物与文档不打包压缩（本地目录天然不需要 zip）。

## 4. 技术取舍与后果

### 4.1 配置读写走官方服务（U32）

| 文件 | 读取方式 | 写回方式 | 是否需要 YAML 解析 |
|---|---|---|---|
| `cordis.patch.yml` | `configEditor.configuration()` 的**原始 override**（完整，不受 schema 投影丢字段影响）+ `settings.describe({ redactSecrets: true })` 的**密钥路径图** | `configEditor.edit(entry, change)`，按条目 `id` 合并 | **否** |
| `package.json` | JSON 解析（Node 内置） | 合并 `dependencies` 与 `dsh.profile.bundles`（有序，取并集时保持顺序） | 否 |
| `pnpm-workspace.yaml` | **原文文本**，不做解析 | 原文覆盖写入，且因 `allowBuilds` 是代码执行许可，**必须展示 diff 并要求显式确认** | 否 |

**收益**：零 YAML 解析代码、零相关依赖；抗 DSH 升级；顺带解决"按 id 合并"与"保留行形式"不可兼得的矛盾。

**代价**：丢失配置文件中的注释与行顺序。

### 4.2 降级能力收窄（必须在 UI 明示）

原 §8.3 承诺"服务缺失时降级为行级合并写入"。**该承诺自本期起不成立**：

| 缺失的服务 | 降级行为 |
|---|---|
| `configEditor` 或 `settings` | **不读写 profile 配置**；只导出 / 导入插件清单、模型信息（只读展示）、skills 与兜底文档，并明确提示"当前 DSH 版本不支持配置的自动还原" |
| `pluginManager` | 只还原配置与文档，插件列入"照文档手工安装"清单 |
| `credentials` | 只输出 `requiredCredentials` 名单，不判断本机是否已配置 |
| `directoryPicker` / 文件选择 | 退化为写入 `<DSH_HOME>\dsh-brittle-backup\` 并提示路径（不维护历史列表） |
| 客户端 UI（`webServer` / slots） | 无 UI，仅保留宿主侧能力（本期无命令 / 工具入口，见 U24） |

**任何服务缺失都不得在 loader 阶段抛错。**

### 4.3 零 dsh-market 代码借鉴

原方案被迫借鉴 dsh-market，是因为 WebDAV 与自重启没有别的实现。本期两者都不做，剩余依赖仅为：读文件、结构化配置、生成 JSON / Markdown、写文件、调用官方服务装插件。

**目标：不搬运 dsh-market 的任何代码。** 设计上仍可参考其思路（如快照与回滚、清单合并），但那属于思路而非代码，MIT 归属问题随之消失。

### 4.4 上限放宽

原 2 MiB / 256 文件是为 Gist 限额定的。本地目录模式下不再是产品约束，仅保留一个**宽松的防爆上限**（防止异常产物撑爆磁盘），超限时明确报错而不是静默截断。

### 4.5 插件仍需自己的工作目录

导出历史取消了，但插件**仍需要**一个内部工作目录（`<DSH_HOME>\dsh-brittle-backup\`）用于：

- 恢复前的**自动快照**与回滚（这是安全机制，不是"历史列表"）
- 临时文件（原子写入的 temp）

快照沿用"保留最近 N 份、超出剪枝"的策略，但这**不在 UI 里做成历史功能**。

## 5. 本期服务依赖

| 用途 | 依赖 | 备注 |
|---|---|---|
| 读结构化配置 / 写回 | `configEditor`（`configuration()` / `edit()`）、`settings`（`describe()`） | 必需；缺失则配置不自动还原 |
| 密钥路径图 | `settings.describe({ redactSecrets: true })` | 权威脱敏来源 |
| 缺 key 提示 | `credentials.describe(ref)` | 只读，永不返回值（U33） |
| 插件安装 / 清单 | `pluginManager`（`installBundle` / `waitForInstall` / `listPlugins` / `listBundles` / `setBundleEnabled`） | 缺失则降级为手工清单 |
| 文件读写 | `fs` 服务 | 不经手 `node:fs` 直连以保持可移植 |
| 目录选择 | `directoryPicker`（宿主）/ `uiWorkspace.pickDirectory()`（客户端） | 导出落点与导入来源 |
| UI | `webServer.register`（宿主）+ `settings.section` 槽位（客户端） | 顶层独立设置页 |

**不注册任何工具给模型，也不提供聊天命令入口**（U24）。

## 6. 本期验收

- [ ] 导出目录结构正确：`backup.json` + `兜底文档.md`（+ 勾选时的 `skills/`）。
- [ ] 勾选项逐项生效：关掉某类内容后产物里确实没有它，且报告如实说明。
- [ ] **产物中零密钥**：正则扫描 + 人工抽查；`redactions[]` 与实际剥离项一致。
- [ ] **兜底文档自包含**：只看文档即可在新机器完成重配（含插件安装命令与可粘贴的配置片段）；且**不含任何主机名 / 账号 / 配置原文**。
- [ ] 导入前 14 项兼容性验证逐项有结论，级别（拦截 / 警告 / 信息）正确。
- [ ] 导出 → 改动 → 导入 → 与原状态一致；且目标机多出的条目**不消失**。
- [ ] 缺 key 提示正确区分"已配置 / 缺失"。
- [ ] 人为制造中途失败 → 断言回滚到操作前；回滚不完整时残留被列出。
- [ ] 有 agent 运行时发起导入 → 断言被拒绝且不写任何文件。
- [ ] **`configEditor` / `settings` 不可用时**：不写 profile 且明确提示（验证降级分支）。
- [ ] 卸载插件后 profile 无残留。
- [ ] 全仓库**无网络代码**（无 `node:https` / `undici` / WebDAV / GitHub 调用）。
